# Ad-hoc challenges

You don't need to build anything in karaweb before using it with
a class. The simplest workflow is:

1. Show pupils how to paint the Kara world (click cells in the
   editor to add trees, mushrooms, leaves, or place Kara)
2. Describe the task verbally or in slides ("get Kara to the
   top-right corner picking up every leaf on the way")
3. Pupils write a program in the mode you've chosen
4. Pupils press **▶ Run** to watch their attempt; they iterate
   until it works

That's it. No configuration, no accounts, no setup.

## When ad-hoc is the right call

- **First lessons** — the bare environment is enough; structure
  gets in the way
- **Pair / group work** — pupils discuss a single shared task,
  no need for per-pupil auto-marking
- **Quick demonstrations** — you set a task on the projector and
  pupils mirror it

## Saving and submitting work

Pupils click **💾 Save** in the header to download a `.json` file
holding their world + program. You decide how they hand it in:

- Upload to your school's learning platform
- Email or shared-drive submission
- Open the file together in class for live review (you click
  **📁 Open** to load it)

The file holds the world and the program for **whichever mode
the pupil was in** when they saved. There's no auto-marking and
no encryption — it's just a portable snapshot.

## When you outgrow ad-hoc

The moment you want any of these, move to
[Challenge books](?tutorial=challenge-books):

- A target world the pupil must reach (with auto-marking)
- Multiple linked exercises ordered into a unit
- A "Show solution" reveal you control
- Code-size limits ("solve this in 12 blocks or fewer")
- Restricted block sets ("no `if` for this challenge — use a
  loop")
- Per-pupil cloud-save submissions you can read later
